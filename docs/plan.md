## Стек

- Next.js (App Router), TypeScript strict, Tailwind v4, shadcn/ui.
- Payload CMS внутри того же приложения: админка на `/admin`, PostgreSQL через `@payloadcms/db-postgres`.
- Формы: react-hook-form и zod v4.
- Yandex Cloud:
  - виртуальная машина с Docker для приложения;
  - Managed PostgreSQL;
  - Object Storage для фото через S3-адаптер Payload.
  - Все данные клиентов хранятся в РФ (152-ФЗ).
- Онлайн-запись: API YCLIENTS (студия уже работает в YCLIENTS).
- Аналитика: Яндекс Метрика.
- Карта: статичная картинка Яндекс Карт со ссылкой на маршрут.
- Тесты: Vitest и Playwright.
- Совместимость версий Next.js и Payload проверю по документации при установке.

### Где расходимся с плейбуком

- Только русский язык, без префикса `/ru/`. Корень `/` и есть главная, редирект на `/en/` не нужен, `hreflang` не нужен.
- Payload вместо Supabase: нужна готовая админка, а данные клиентов должны храниться в РФ.
- Yandex Cloud вместо Vercel по той же причине.
- Яндекс Метрика вместо Plausible.
- Строки интерфейса лежат в `src/i18n/ru.ts` без next-intl.

## Атмосфера и анимации

Сайт должен ощущаться как сам кабинет: тёплый свет, медленный ритм. Анимации спокойные, ни одна не мешает читать или записываться.

### Что анимируем

- **Первый экран.** Фото кабинета очень медленно приближается (около 20 секунд). Заголовок проявляется построчно (GSAP SplitText).
- **Золотые линии.** Разделители и дуга из логотипа прорисовываются при прокрутке (SVG stroke).
- **Фото на всю ширину.** Лёгкий параллакс. Фото открываются шторкой-маской, как если бы раздвигали занавес.
- **Тёмная секция с логотипом.** Свечение медленно пульсирует, как свеча.
- **Карточки услуг и кнопки.** На наведение реагируют цвет и лёгкий сдвиг, без масштабирования.
- **Мрамор.** Текстура едва заметно движется в фоне некоторых секций, только на CSS.

### Ограничения

- Анимируются только `transform` и `opacity`.
- Если включено `prefers-reduced-motion`, вместо движения контент просто появляется.
- Если скрипт не загрузился, весь контент виден.
- На телефоне параллакс слабее, тяжёлые эффекты отключены.
- Проверка:
  - скриншоты Playwright в нескольких позициях прокрутки;
  - прогон с `reducedMotion: 'reduce'`;
  - замедление CPU в 4 раза: задач длиннее 50 мс быть не должно.

### Адаптивность

- Вёрстка mobile-first, проверка на 375 px, планшете и десктопе.
- Фото отдаются через `next/image` с размерами под экран (AVIF, WebP).
- Фото первого экрана грузится сразу, остальные лениво.

## Запись

Решение от 2026-11-01: запись идёт через YCLIENTS, которым студия уже пользуется (кнопка «Записаться онлайн» на Яндекс Картах). Расписание одно, его ведёт Олег в YCLIENTS. Сайт берёт свободное время из YCLIENTS и создаёт запись там же через API.

### Что видит клиент

1. Выбирает вид массажа.
2. Видит календарь на 30 дней вперёд в дизайне сайта: даты и свободное время из YCLIENTS. Переключение по неделям и фильтры: вид массажа, время суток (утро, день, вечер).
3. Вводит имя, телефон, комментарий и ставит галочку согласия на обработку ПД.
4. Если в YCLIENTS включено подтверждение по SMS, вводит код.
5. Получает экран «Вы записаны» с датой, временем и правилом отмены.

### Что получает Олег

- Запись появляется в YCLIENTS, как сейчас приходят записи с Яндекс Карт. Уведомления присылает YCLIENTS.
- Рабочие часы, выходные, перерывы и длительности сеансов он меняет в YCLIENTS.

### API YCLIENTS

- Адрес `https://api.yclients.com/api/v1`, заголовок `Authorization: Bearer <партнёрский токен>`.
- Методы онлайн-записи: `book_services/{company_id}`, `book_dates/{company_id}`, `book_times/{company_id}/{staff_id}/{date}`, `book_check/{company_id}`, `book_code/{company_id}` (SMS-код), `book_record/{company_id}`.
- Запросы идут только с сервера Next.js. Токен лежит в переменных окружения и в браузер не попадает.
- Свободное время запрашивается без кеша. Список услуг и цен кешируется на час.
- Если YCLIENTS не отвечает, клиент видит понятную ошибку и телефоны студии.

### Данные

- Источник правды по ценам и длительностям — YCLIENTS. В Payload у вида массажа хранятся описание, фото, противопоказания, FAQ, SEO и ID услуги в YCLIENTS.
- Персональные данные клиентов на нашем сервере не хранятся: они передаются в YCLIENTS (российский сервис). Согласие на обработку ПД и политика обязательны.
- Коллекции `bookings`, `days-off` и глобальные настройки `schedule` удаляются, когда доступ к API подтвердится. До этого остаются запасным вариантом.

### Безопасность

- Защита от спама: honeypot и ограничение частоты запросов по IP на нашем сервере до обращения в YCLIENTS.
- Все входящие данные проверяются zod на сервере.
