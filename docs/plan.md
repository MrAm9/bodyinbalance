## Стек

- Next.js (App Router), TypeScript strict, Tailwind v4, shadcn/ui.
- Payload CMS внутри того же приложения: админка на `/admin`, PostgreSQL через `@payloadcms/db-postgres`.
- Формы: react-hook-form и zod v4.
- Yandex Cloud:
  - виртуальная машина с Docker для приложения;
  - Managed PostgreSQL;
  - Object Storage для фото через S3-адаптер Payload.
  - Все данные клиентов хранятся в РФ (152-ФЗ).
- Уведомления о записях: бот в Telegram.
- Аналитика: Яндекс Метрика.
- Карта: статичная картинка Яндекс Карт со ссылкой на маршрут.
- Тесты: Vitest и Playwright.
- Совместимость версий Next.js и Payload проверю по документации при установке.

### Где расходимся с плейбуком

- Только русский язык, без префикса `/ru/`. Корень `/` и есть главная, редирект на `/en/` не нужен, `hreflang` не нужен.
- Payload вместо Supabase: нужна готовая админка, а данные клиентов должны храниться в РФ.
- Yandex Cloud вместо Vercel по той же причине.
- Яндекс Метрика вместо Plausible.
- Строки интерфейса лежат в `src/i18n/ru.ts` без next-intl.

## Атмосфера и анимации

Сайт должен ощущаться как сам кабинет: тёплый свет, медленный ритм. Анимации спокойные, ни одна не мешает читать или записываться.

### Что анимируем

- **Первый экран.** Фото кабинета очень медленно приближается (около 20 секунд). Заголовок проявляется построчно (GSAP SplitText).
- **Золотые линии.** Разделители и дуга из логотипа прорисовываются при прокрутке (SVG stroke).
- **Фото на всю ширину.** Лёгкий параллакс. Фото открываются шторкой-маской, как если бы раздвигали занавес.
- **Тёмная секция с логотипом.** Свечение медленно пульсирует, как свеча.
- **Карточки услуг и кнопки.** На наведение реагируют цвет и лёгкий сдвиг, без масштабирования.
- **Мрамор.** Текстура едва заметно движется в фоне некоторых секций, только на CSS.

### Ограничения

- Анимируются только `transform` и `opacity`.
- Если включено `prefers-reduced-motion`, вместо движения контент просто появляется.
- Если скрипт не загрузился, весь контент виден.
- На телефоне параллакс слабее, тяжёлые эффекты отключены.
- Проверка:
  - скриншоты Playwright в нескольких позициях прокрутки;
  - прогон с `reducedMotion: 'reduce'`;
  - замедление CPU в 4 раза: задач длиннее 50 мс быть не должно.

### Адаптивность

- Вёрстка mobile-first, проверка на 375 px, планшете и десктопе.
- Фото отдаются через `next/image` с размерами под экран (AVIF, WebP).
- Фото первого экрана грузится сразу, остальные лениво.

## Запись

### Что видит клиент

1. Выбирает вид массажа и длительность.
2. Видит календарь на 30 дней вперёд со свободными и занятыми слотами. Имён в календаре нет. Переключение по неделям и фильтры: вид массажа, длительность, время суток (утро, день, вечер), «только свободные».
3. Вводит имя, телефон, комментарий и ставит галочку согласия.
4. Получает экран «Заявка принята. Олег подтвердит запись звонком или сообщением в течение часа» с датой и временем.

### Что получает Олег

- Сообщение в Telegram с данными заявки и кнопками «Подтвердить» и «Отменить».
- В админке:
  - список записей с фильтрами;
  - смена статуса;
  - запись клиента вручную, если тот позвонил.

### Правила по умолчанию

Олег меняет их в админке:

- запись не позже чем за 30 минут до начала;
- запись не дальше чем на 30 дней вперёд;
- между сеансами 15 минут;
- шаг слотов 30 минут;
- рабочие часы 10:00–22:00 каждый день, выходные дни и перерывы задаются отдельно;
- отмена или перенос не позже чем за 3 часа, по телефону или в Telegram;
- без предоплаты.

### Данные в Payload

- `services`: название, slug, описание, для кого, противопоказания, варианты длительности и цены, порядок, активность, SEO-поля.
- `bookings`: услуга, начало, конец, имя, телефон, комментарий, статус (новая, подтверждена, отменена, завершена), согласие на ПД с датой.
- `schedule` (global): рабочие часы по дням недели, буфер, шаг, минимальное время до записи, горизонт записи.
- `days-off`: выходные и перерывы.
- Тексты страниц, мастер, контакты, FAQ.
- `users`: доступ в админку только для Олега и разработчика.

### Надёжность и безопасность

- Две записи на одно время база не пропустит: ограничение exclusion на пересечение интервалов в PostgreSQL.
- Новая заявка сразу занимает слот. Отменённая освобождает его.
- Расчёт свободных слотов вынесен в чистую функцию с тестами.
- Защита от спама: honeypot и ограничение частоты запросов по IP.
- Все входящие данные проверяются zod на сервере.
- Публичный API отдаёт только занятые интервалы, без персональных данных.

### Telegram

- Бот не может написать человеку по @username. Получатель (сначала @MrAm959, потом рабочий аккаунт) один раз нажимает /start в боте, после этого его chat_id сохраняется в админке.
- Если Telegram недоступен, заявка всё равно сохраняется и видна в админке. Запасной канал (почта или SMS) отложен до решения владельца.

## Открытые вопросы и плейсхолдеры

- Медицинская лицензия. Без неё вместо «лечебного» пишем «массаж спины и шеи», слово «врач» не используем.
- Специальность по диплому (сам диплом или вкладыш), аккредитация, курсы, стаж, фото Олега.
- Реквизиты ИП или ООО: ИНН и ОГРН для подвала и политики ПД.
- Цены: черновые по рынку Москвы (Профи.ру, 2026), помечены `TODO(content)` до подтверждения.
- Логотип в векторе (SVG) на прозрачном фоне.
- Фото кабинета в полном разрешении, лучше реальные.
- Почтовый индекс, подъезд, этаж, домофон, парковка.
- С какого возраста детский массаж, с какого срока массаж для беременных.
- Рабочий Telegram для уведомлений (на время теста @MrAm959).
